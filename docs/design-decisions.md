## 0. 已拍板的设计方向（用户未答复 4 问，按推荐项执行）

| 维度 | 决策 | 理由 |
|---|---|---|
| 形态 | **教师端 Web 应用（单角色）**，含课堂页 + 报告页 | 流的 `USER_INPUT` 就是老师说的话、`query` 就是老师原话；没有学生端输入通道 |
| BFF | **Node 22 + TypeScript**（内置 `http`，零框架依赖） | 与前端共享 SSE 指令类型；SSE 透传不需要框架 |
| 前端 | **Vite + React 19 + TS，多页（MPA）** | 与 `ai-agent-frontend-framework` 基线一致；每个入口独立 HTML，刷新/深链接稳 |
| UI | **讲台风**：中间对话流、右侧学生席 + 指标、顶部课堂状态条 | 上课时"学生有没有接住"比"聊天记录"更重要，指标必须常驻可见 |
| 运行模式 | **默认 `mock`，一条配置切到 `coze`** | 真流有 P0 阻塞（见 §3），mock 让界面、状态机、卡片、报告全链路先跑通并可视化验收 |
| 工具链 | 便携 Node 落在 `.toolchain/`，不进 PATH、不装系统 | 本机原本无 Node |

## 3. 新发现的阻塞项（P0/P1，契约里没有）

### 3.1 【新 P0】进入「继续课程」分支会因缺少入参直接抛异常

`1021290`(更新 K)、`152987`(学生参数调整)、`152181`(KCE 重排序) 三个代码节点的注释与取值都写的是 `k1..k4` / `slot_ce1..slot_ce4`，但 **YAML 里实际只声明了 `k1,k2,k3` 三个输入，`1021290` 甚至一个 `k{n}` 输入都没声明**（它的 `node_inputs` 只有 `number/K1/K2/K3/mastery1..3`）。

- `1021290` 的代码读 `params.get("K1")`——这个 key **在 node_inputs 里根本不存在**，取到 `None`；
- `152987` 的 `as_list(None)` → `[]`，`k_map` 为空 → `valid` 为空 → **9 个输出全为空数组**；
- 下游 `152181` 同样拿不到数据，`195160` 输出全 0。

结论：**第一次「继续课程」会把手上的 K/C/E 全部清成空**，而且不会报错。
→ 修法：三个节点补齐 `k1..k3`/`slot_ce1..ce3` 声明，或把代码里 `MAX_SLOTS` 相关位置全部对齐到 3。**这一条必须在联调前修。**

### 3.2 【新 P0】课中回答只在"知识点相关"时才落库

`101122 → true_5` 同时进入 `1814058`(知识点相关性判断) 和 `1304497`(知识点匹配)，然后 `1603361` 只看 `1814058.boolean`。
若老师这一句与 `names` 里任何知识点都不相关（表扬、点名、闲聊式点评都是），就走 `false` 分支：
- 跳过 `1405727/1892878/1805030/1557351` → **这一轮不写数据表**；
- 但继续走 `1026746` → 学生照样发言、`turn` 照样 +1。
→ 后果：报告（读整张表）会**缺掉一半的课堂环节**；`turn` 与表内行数不再一一对应。

### 3.3 【新 P0】会话历史在"开课前最后一次初始化"时被清空

`197096 → 159331`：输出「课堂已经开始」后立刻清空会话历史。
`159331` 的入参是 `CONVERSATION_NAME`（start 节点参数，默认 `Default`）。这意味着：
- 前端必须保证每次 `/v3/chat` 都传同一个 `CONVERSATION_NAME`；
- 如果这个参数没传（`Default`），会清掉**同名 Default 会话**——在 chatflow 里通常就是当前会话，但**语义上它清的是"按名字找的会话"，不是"当前 conversation"**，需在 Coze 侧实测确认。

### 3.4 【新 P1】选学生问答没有人数上限，也没有"至少 1 人"校验

`181544` 的 `limit: 3` 只是 UI 提示，`198844` 会解析出任意多数字：
- 输入 `1,2,3,4,5,6` → `173665` 查出 6 条 persona → `142720` 批处理跑 6 次 LLM（成本 ×6）；
- 但下游槽位只有 3 → **后 3 人静默丢弃**（与契约 P0-2 同源，现已确认是**数据层**问题）。

### 3.5 【新 P1】`113458` 的 `NAMES` 写死为 3 人，且 `answer2` 恒为空

- `NAMES = ["小陈","小新","小星星"]` → 若老师选了 `4=赵六`，`1573750` 会生成"赵六：…"，但 `113458` **只认前三个名字**，赵六的台词被整体过滤 → `1816786` 输出空串。
- `_split()` 遇到 `speech[-1][0] == name` 会**合并**成一段，所以正常情况 `answer1/answer2/answer3` 里 2、3 恒为空。契约 §4.2 说"一轮可能连推多条"是对的，但**文案上通常只有 1 条非空**。

### 3.6 【新 P1】`195846`(turn+1) 的输入 `turn` 在首次开课时为空

`1267860` 读 `int(params.get("input") or 0)`，`or 0` 兜住了 `None`，**不会崩**；但首次 turn 从 0 → 1。这一条是**没问题**的，仅记录：`turn` 从 1 开始，表里的主键 `turn` 与「第 N 轮」一致（不是 0 基）。

### 3.7 【新 P1】报告读的是全表，且查询条件为空

`155522` 的 `conditionList: []` + `limit: 100` → 读整张表。与 P0-1（无租户字段）叠加，报告会**混入别的课堂**的数据。

## 4. 一期的取舍

| 项 | 一期做法 |
|---|---|
| 数据表租户隔离 | BFF 侧加**单活跃课堂锁**（契约 P0-1 方案 B），并在报告页标注"共享表模式" |
| 选学生人数 | UI 强制 1~3，BFF 校验，超出 `BAD_REQUEST`（不是静默丢弃） |
| 继续课程丢 K/C/E | **不改流**，BFF 收到全员 0 值时给出 `state` 警告标记，报告页标注"该轮指标缺失" |
| 结课清理 | BFF 在 `close` 时只做本地标记，不调 Coze；同时在 README 明确提示需在 Coze 侧补 `159331` |
| 报告 | 一期先把 `https?://\S+` 抠出来做成下载卡；自渲染 HTML→PDF 列为二期 |
